# ab-normalize

1. This is the only description of normalizing a task: ab-adopt runs the same steps against a staging copy with `--adoption PATH` on every command. Read `tracker status` to resolve the bound project scope. Mark the completed tasks in that scope at once with `tracker normalized --done [--project P] [--recursive]`: a Done task has nothing left to normalize. Use `tracker search --exclude-label ab:normalized` with the selected `--project`/`--recursive` scope for the remaining candidates. An empty result ends the pass. Never fetch every task's full text to decide eligibility. Users remove `ab:normalized` to request reprocessing after edits; no content-change detection is needed.
2. Read each candidate with `tracker get ID` and recheck its marker before writing; skip tasks already marked. Preserve language, scope, unrelated text, assignments and historical progress. Normalize Goal, Context, Acceptance and Validation from existing evidence; extract only justified checklist items. Record unresolved human decisions explicitly and leave that unfinished work in Backlog for ab-interview. Do not invent requirements, implement, decompose, clone or rebind the project.
3. Apply ab-tracker's relation and priority evidence rules to candidates. Search existing tasks through compact `tracker search QUERY` results without excluding marked tasks; read full descriptions only for plausible relation candidates. An unmarked task can depend on a marked one. Change justified relations involving candidates, including inverse links, but do not renormalize marked descriptions or reevaluate the marked backlog's priorities. Stay in the selected project tree; ask before expanding external edits.
4. Use tracker commands for updates, relations, priority and short task-language explanations of substantial changes. Do evidenced edits autonomously within the authorized scope; ask about material uncertainty. Read back the affected tasks and verify the intended fields and relations. After all normalization edits, journal writes and verification succeed, run `tracker normalized ID` last. Failed or interrupted processing stays unmarked; resume from live state without duplicating completed writes or comments.
5. `ab:normalized` means processing finished, independently of Ready/Done or completeness for implementation. Explicit unresolved questions in Backlog do not prevent marking. Remove it with `tracker normalized ID --undo` to reprocess. Preserve other labels and never rename/delete global labels. Report processed tasks and unresolved decisions briefly; keep state in the tracker.
