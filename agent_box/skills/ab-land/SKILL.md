# ab-land

Invoking this skill authorizes the normal sequential fix/review/merge workflow, subject to repository policy. Ask the user on ambiguity or disputed scope; unattended runs return needs-human. Never bypass branch protection or force-push.

1. Read the parent task and `workflow inspect PARENT` on its branch for the effective configuration source, merge mode, scope and review triggers; never choose the route from host/default config inside a container. Then use `workflow land PARENT inspect`. In GitHub mode it finds the PR by parent branch and base; several matches stop instead of guessing. Confirm PR identity and head, inspect CI, unresolved threads and comments. In local mode it reports the exact local task/base refs, ancestry and completion blockers; GitHub is not contacted. Use targeted read-only scouts only when useful, within configured scout_limit. No parallel implementation.
2. `workflow land PARENT request-review` uses configured cloud Codex/Claude or recommends local review in GitHub mode. Local merge mode uses fresh ab-review and refuses explicit cloud review without contacting GitHub. Respect wait_seconds where applicable; absence of a response is not approval.
3. Use `tracker claim PARENT --resume` to return the assigned Review task to Doing. Address valid feedback sequentially with a bounded worker or primary for tiny changes. Preserve task-language progress. For disputed/out-of-scope requests ask the user, update affected tasks and dependencies, then respond. Reviewers remain read-only; primary handles comments and thread resolution through gh after verifying the fix.
4. For direct fixes record `workflow writer PARENT --provider ACTUAL` while Doing, then return to Review after acceptance. Commit fixes, run the project's validation with `workflow validate PARENT -- COMMAND ARGS`, then request a current-head review or run ab-review according to configured policy. In GitHub mode, without a current-head GitHub approval, obtain a fresh independent PASS even when off/auto skips local review: use `workflow run PARENT --role reviewer --brief FILE --primary PROVIDER`, or `workflow prepare PARENT --role reviewer --brief FILE` followed by ab-review's native spawn/report path with exact configured routing. Each verdict uses a new reviewer instance, never followup/resume of an earlier one. SKIPPED does not satisfy this GitHub requirement. Local merge mode retains policy-based skipping and also permits explicit user acceptance of the inspected result via `workflow approve PARENT --scope DIGEST --reason TEXT`. This records human acceptance, never independent PASS; no-delegation instructions alone do not authorize it. Changed scope, a worker or a new review retires the human decision. Push the parent safely only in GitHub mode.
5. Repeat inspect/fix/validate/review at most configured max_rounds and stop on repeated findings without progress. Keep a short iteration summary in the tracker; do not reset the bound by restarting the skill. CI failure, stale review, unaddressed threads, uncertainty or timeout prevents merge.
6. In GitHub mode, when current-head acceptance, validation and repository policy agree, `workflow land PARENT merge [--method squash|merge|rebase]` pins the expected head; omitted method defaults to squash. A queued merge is not Done, and the returned merged PR must retain the exact head/base and actual merge identity. In local mode, run `workflow land PARENT merge` with no method: it requires clean local refs and fast-forwards the local default base to the exact validated task head. With auto_push enabled (default within opt-in workflow), it publishes only that exact base head to the unique effective origin using available Git credentials, with no GitHub API requirement or task-branch publication; false completes locally without push. Required publication precedes Done and cleanup. Push failure preserves the local merge, Review and task branch. If publication or the tracker update fails, retry `workflow land PARENT reconcile` (from the base in local mode, the parent branch in GitHub mode); it proves integration and never repeats the merge. Local retry requires the base to equal the exact accepted head before publication, rejects unknown/diverged remote or changed default, and safely accepts an already-published exact head after tracker failure. Never force repair; explicit auto_push=false permits local-only recovery.
   Local reconciliation also requires the disposable acceptance snapshot saved before Git mutation: exact task head, base identity, unchanged requirements, validation and review satisfying the current policy against the original diff, or explicit human acceptance of that scope. Ancestry alone is not acceptance. A missing/stale snapshot leaves the parent Review: switch to the task branch, rerun `workflow validate PARENT -- COMMAND ARGS` and ab-review as required (or obtain new explicit human acceptance of the complete result), then `workflow land PARENT merge` to recheck acceptance and return to the base. For fresh acceptance of already-integrated work, auto/always cannot justify SKIPPED or PASS from an empty base diff; review or human acceptance must cover the complete implementation and requirements using code/Git history. Off still requires validation. If review scope is unclear, stop with INCONCLUSIVE; never reset the base or mark Done manually to bypass recovery.
7. Report `cleanup` outcomes separately from successful merge/Done. `workflow.cleanup_local_branches` and `workflow.cleanup_remote_branches` are independent and off by default; enabled cleanup runs only after successful completion and covers the parent branch, leaving child refs alone. Preserve current/worktree/base/symbolic/ambiguous or moved refs. GitHub proof is the exact merged PR head/base, including squash/rebase; local remote cleanup also needs the head in the live published origin base. Cleanup and Done reconciliation never publish the base or force-repair a branch. If the parent remains checked out, explain the preservation; after the user or coordinator switches to the base, `workflow land PARENT cleanup` safely retries the configured policy for the Done parent. It does not merge or update tracker state, and missing refs are no-ops. Do not enable cleanup settings merely to finish landing.
