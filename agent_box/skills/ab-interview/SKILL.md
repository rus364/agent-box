# ab-interview

Read the task, comments, related tasks and relevant repository code first. Search older decisions and inspect existing libraries before asking questions the evidence can answer.

Identify unresolved decisions in dependency order. Ask one material question at a time in the user's language, with 2-4 concrete options and a recommendation when useful. Challenge assumptions with a concrete example, failure case or constraint; do not conduct an exhaustive interrogation for obvious work.

Stop when remaining choices can safely be decided during implementation. Update the task's Goal, Context, Acceptance and Validation in its language; preserve unrelated text and summarize important decisions in a comment. Explain changed scope and relations. Keep the plan in the tracker, without a parallel repository task database. Already approved work does not need another approval ceremony.
