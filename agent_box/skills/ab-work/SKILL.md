# ab-work

1. Read `tracker get ID`, related history, repository guidance, and `tracker ready`. Resolve ambiguity with ab-interview. Read `config show` for the effective configuration and its source; inside a container host/default `load_config` is not the workflow configuration. Only the coordinator calls `workflow begin ID --primary PROVIDER`; inspect its reported merge mode, and use --resume only after inspecting an interrupted task and its branch. Branch names follow the task ID and the base branch is origin's live default; neither is configured or recorded anywhere. A branch already pushed for the task is adopted, in a fresh clone too; ambiguous or diverged branches stop instead.
2. Work on one implementation task at a time. Without a task tier or applicable worker override, `workflow prepare ID --role worker --primary PROVIDER` and `workflow run` return `work-in-current-session`: implement directly without changing the current provider/model/effort or inventing a tier label. This action retires acceptance and records the primary writer; it is not a completion receipt. Optional `--session-model MODEL --session-effort EFFORT` must come from verified active-session facts, never a tier matrix or profile name. For an explicit task tier (or explicit `--tier` invocation override), `workflow prepare ID --role worker --primary PROVIDER` selects model/effort from workflow.tiers unless the worker override applies. `workflow.worker.override.enabled` uses independent Codex/Claude candidates without a tier; `apply_to_tiered` also replaces tier candidates. Only the model source changes: provider policy, weights, usage limits and fallback remain. Empty models disable candidates with no return to session/tier models. Reviewer and scout settings are independent; preserve the effective tier, including null. Use either an exact available profile or explicit spawn parameters supported by the live tool, without an overriding custom agent. native_profile_ready checks only the installed profile; false does not forbid explicit spawn. native_explicit_settings are required values, not discovered capabilities. Verify provider, model availability, effort support, profile precedence, defaults and inheritance; a role name or prompt proves nothing. For Codex explicit spawn use fresh context (fork_turns="none" when supported), pass both model and reasoning_effort, and avoid a named tier profile. Never assume built-in names cannot be shadowed. For effort=default or unknown/unsupported capabilities, use managed CLI. Managed execution uses `workflow run ID --role worker --primary PROVIDER --brief FILE`. Never launch nested agent-box sessions. Do not reschedule an active worker based on changing usage or configuration. Report actual provider/model/effort against the prepared route even if configuration changes after prepare.
3. Handoff in English: task ID, bounded scope, relevant paths, decisions, validation, and expected report. Pass the `repository_instructions` that `prepare` returns to the delegate. A worker changes project files in the working tree and returns a report; it never commits, pushes, switches branches, writes the tracker or touches GitHub, and it never edits `.agent-box.json`. Progress and evidence belong in the report: you decide what to record afterwards. Keep the `handoff` descriptor to yourself; it names one delegation, bound to its repository, tracker project, task, scope, role and tier, so each delegation needs its own `prepare`. Accepting a worker report drops any earlier validation and review acceptance, and is refused if the branch or HEAD moved meanwhile. For native reports use `workflow report ID --role worker --primary PROVIDER --provider ACTUAL_PROVIDER --model ACTUAL_MODEL --effort ACTUAL_EFFORT --scope SCOPE --handoff DESCRIPTOR --file FILE`. Add `--fallback-reason REASON` for a fallback candidate, explaining why the preferred route could not run. Exact route checks precede acceptance changes; never substitute configured values for unknown actual settings. For untiered work with unknown exact settings, omit `--model/--effort` and use `--session-inherited` only after actual execution with settings preserved; prepared concrete settings still require exact reported values. CLI reports are checked and recorded automatically.
4. Investigate failures before fixes: reproduce, trace the cause, test one hypothesis. Useful regressions must fail for the intended reason. Check actual consumers/requirements; prefer local fixes or reuse. Justify why smaller changes cannot suffice before redesign; preserve required error/safety/compatibility checks. Avoid needless layers, duplicated state/checks, speculative generalization and tests restating implementation.
5. New dependencies, contradictions or overlap with future work require the user's decision; update all affected tasks and relations. Provider errors require inspecting side effects before retrying; never silently restart a partially completed worker.
6. Primary reviews the worker's evidence for completeness, records task-language progress and checks acceptance items in the tracker itself, commits the implementation, then runs `workflow validate ID -- COMMAND ARGS`. Read `workflow inspect ID` for the current scope, effective route and exact review triggers. For direct-primary changes record `workflow writer ID --provider ACTUAL` before review, including resumed fixes. This is mechanical validation, not independent code review. Use ab-review according to configured policy. For a local parent only, explicit user acceptance of the inspected result may instead be recorded with `workflow approve ID --scope DIGEST --reason TEXT`; a request to avoid subagents is not acceptance. Never invent independent PASS, call the tracker adapter directly, or merge manually to bypass a refusal.
7. Verify findings against code/requirements before fixing; use ab-review's evidence and proportionality rules, including concrete complexity cost and a simpler behavior-preserving alternative. Push back with evidence; escalate material disagreement without self-awarding PASS. Journal valid findings in task language, uncheck only contradicted items, return to Doing, then fix/commit/validate/review sequentially. Failed/abandoned attempts consume the review budget; scope changes never reset it. Follow ab-review to record a user's additional allowance; stop on ambiguity or no progress.
8. `workflow finish ID` integrates a completed subtask into the parent and marks it Done; configured auto-push publishes only the parent in GitHub merge mode and publishes no task branches in local mode. Local ab-land publishes the accepted base after fast-forward when auto_push is enabled (the default within opt-in workflow). Repeat with the next ready subtask. Validate/review the complete parent diff, then finish the parent to Review. Follow the reported route: offer ab-pr in GitHub mode or use ab-land for a local fast-forward. Parent Done requires proven integration into the base.
