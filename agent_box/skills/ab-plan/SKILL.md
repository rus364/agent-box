# ab-plan

1. Read the current task, applicable repository guidance, dependencies and relevant decisions. Search other tasks when overlap or missing context is plausible. Use ab-interview only for material unanswered choices.
2. Inspect existing code and reuse suitable implementations. Research current maintained libraries and stable versions from official sources only when the work presents a material dependency choice; record the choice, version/date and constraints. Do not perform dependency research for an exact task with no dependency decision.
3. Consider scouts only for distinct bounded unanswered questions that materially affect a decision or avoid substantial repeated reading. Quick lookup stays with the coordinator; duplicate scouts are prohibited. Only the coordinator dispatches scouts, never workers or scouts. Prepare each with `workflow prepare TASK --role scout --tier 0 --primary PROVIDER --question "ONE QUESTION" --brief FILE`; keep the question separate from Goal/Acceptance/Validation. Pass `delegate_handoff` unchanged as the complete initial bootstrap to a fresh read-only agent. It references the canonical read-only input by path and SHA-256; never inline or reconstruct it. Several scouts may overlap up to effective `scout_limit`: managed runs enforce shared repository slots; native launches are coordinator-counted because CLI processes cannot own native subagent leases. Consume the prepared `managed_command` or native `report_command`; never reschedule. Reports contain English facts, source locations and uncertainty, not reviewer verdicts.
4. Keep small work as one task with a checklist. For larger work create subtasks in the same project, each understandable and testable in one context. Parent is the deliverable/spec; do not create a project per spec or setup/test pseudo-tasks.
5. A task tier is optional. Assign tier 1-3 only when an explicit configured route is wanted; never fabricate one to pass readiness. Overrides do not change the stored tier, and tier 0 is only for scouts. Add real dependency relations. Ask the user about material unresolved alternatives or conflicting scope, then update each affected task once the decision is made; do not reopen an accepted decision without new evidence.
6. Record acceptance and proportionate validation. Prefer a few behavioral regression tests over tests mirroring functions. Mark fully specified unblocked tasks Ready. One parent branch and one parent PR; subtasks execute and integrate strictly sequentially.

The coordinator may select concise evidence for a delegated worker using `--facts FILE` at prepare and the same file at managed run. JSON contains exact `task`, current `scope`, and 1–12 `facts`, each with `text`, 1–6 `sources` and optional `limitations` (16 KiB total; strings limited to 1000/300/500 characters respectively). Strict keys/types apply. These selected facts reduce repeated reading/context without promising token savings. Never pass raw scout output, conversations, comments or agent history. Reviewer requirements remain independent.
