# ab-plan

Before coordinating work, read `agent-box workflow behavior --role coordinator`; follow its effective instructions and startup guidance notice. Assigned delegates use the behavior in their assignment.

1. Read the current task, applicable repository guidance, dependencies and relevant decisions. Search other tasks per ab-tracker when overlap or missing context is plausible; use `--include-done` for past decisions or completed work. Use ab-interview only for material unanswered choices.
2. Inspect existing code and reuse suitable implementations. Research current maintained libraries and stable versions from official sources only when the work presents a material dependency choice; record the choice, version/date and constraints. Do not perform dependency research for an exact task with no dependency decision.
3. For a bounded research question that would otherwise need substantial reading, follow `workflow inspect ID` `execution.scout`: `self` means research it yourself; `delegate` names the native `ab-scout` profile for your provider, else run `workflow delegate ID --role scout --brief FILE`; the brief states the goal, the one question, scope and limitations. Keep quick lookups yourself and never launch duplicate scouts.
4. Keep small work as one task with a checklist. For larger work create subtasks in the same project, each understandable and testable in one context. Parent is the deliverable/spec; do not create a project per spec or setup/test pseudo-tasks. Write new descriptions as four second-level sections in the order Goal → Context → Acceptance → Validation (headers in the working language, ab-tracker; Acceptance and Validation as `- [ ]` items). Implementation tasks name reference documents as `path#heading` with purpose; verify the sections. Keep an existing reference section’s heading and location, in the working language; if absent, add one under Context. Missing decisions need clarification, not invented links.
5. A task tier 1-3 is optional and selects worker, Plan sync and reviewer lists `tiers.N` only while `workflow.use_tiers` is on; scouts have no tier. A tier the user sets wins. Otherwise set one only when tiers are on, that tier's list is configured, and the task's difficulty or risk clearly differs from what the role's `models` serve (higher is harder); never to pass readiness, and never derived from session pins or list contents. Add real dependency relations. Ask the user about material unresolved alternatives or conflicting scope, then update each affected task once the decision is made; do not reopen an accepted decision without new evidence.
6. Assess priority using ab-tracker’s evidence rules when preparing or creating tasks. Record acceptance and proportionate validation. Prefer a few behavioral regression tests over tests mirroring functions. Mark a fully specified subtask Ready as soon as it is described; blockers, not the column, decide when work may start, and `tracker ready`/`claim` already refuse a blocked task. After preparing tasks, run `workflow sync PARENT --event plan` through ab-sync; it follows Plan sync settings. One parent branch and one parent PR; subtasks execute and integrate strictly sequentially.
