# ab-setup

1. Read repository instructions and `agent-box tracker status`. Resolve the user's provider, server and project. Credentials and integration permissions belong in global `agent-box config`; `config --project` edits allowed project policy. Never put secrets in Git.
2. Inspect `tracker projects` and `tracker setup --project ID [--recursive|--no-recursive]`. Omitting the scope flag preserves the saved scope for the same provider/server/project; a new binding defaults to root only. The preview reports, per project, the kanban view it resolved and the lifecycle columns it recognized. All five states are mandatory: Backlog, Ready, In progress, In review, Done. Vikunja: each project needs exactly one kanban view with manually managed buckets; Done follows the view's own done bucket when it has one. GitHub Projects: `--project` takes owner/number or the project URL, there are no subprojects, states are the Status field's options, and the global token is a classic one with scopes `repo` and `project`.
3. Setup never writes view or column IDs. `tracker provider vikunja board init PROJECT [--recursive]` adds the missing lifecycle columns and sets the view's done column; inspect the dry run before `--apply`. It only adds, so an unrecognized title, an ambiguous match or a filter-built board stays reported for the user to rename, disambiguate or rebuild. With `--recursive`, every project under the root must satisfy this, because all of them take part in the workflow. For GitHub, `tracker provider github board init PROJECT` plans the Status options and the Priority options Immediate, Urgent, High, Medium, Low, highest first, renaming the Board template's Todo and P0-P2 with their IDs, so cards keep their values; inspect the dry run before `--apply`. Setup and status warn about enabled pull request workflows; ask the user to turn them off under the project's Workflows.
4. Run `tracker setup --project ID [--recursive|--no-recursive] --apply`. Review `.agent-box.json`, the managed block at the start of `AGENTS.md`, and the import in an existing `CLAUDE.md`; setup never creates that file. Setup preserves project overrides and outside text and refuses edited blocks. Resolve refusals with the user, never overwrite them.
5. Jira: the project is its key; there are no subprojects. Lifecycle comes from exact native workflow status names across all issue types, not agile board columns. Configure missing statuses and transitions in Jira administration; automatic board/workflow provisioning is unsupported. Global connection: Server/DC PAT with username empty, or Cloud email in username and a classic API token. Jira adoption is in place with ab-normalize after workflow setup; cloning is unsupported. For Vikunja, offer ab-adopt when tasks already exist; GitHub is normalized in place after board init. Setup alone does not normalize tasks.
6. The base branch is origin's default branch, read from Git; there is nothing to configure. Verify `tracker status` and `tracker ready`. Commit the portable binding/instructions when appropriate. On another device, configure the same provider/server globally; project binding remains in the clone. Host and container both use `agent-box tracker`.
